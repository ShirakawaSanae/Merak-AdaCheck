# 2026-09-24 研究提案讨论：从逻辑冗余到可恢复的物理保护

> 定位：论文构思和可证伪的研究方案，不是实验结果报告，也不修改现有实验授权。本文以当前 `AGENT.md`、`docs/ckpt_grouping_paper_outline.md`、`docs/ref_survey.md`、`TWO_NODE_RUN_LOG.md` 和已记录的 r225/r229 严格套件为本项目事实依据；以论文原文、而非公开代码未实现的路径，作为已有工作的设计依据。2026-09-24。这里的“任意并行”指满足明示对象与状态转换合同的合法布局，绝不等于已对任意 DP/TP/PP/EP/ZeRO 布局端到端验证。

## 一、先给研究判断：问题成立，但必须选准边界

可作为论文主张的命题是：**冗余检测使训练状态的逻辑等价关系显式化，但“什么可以不重复保存”并不能决定“谁向哪个独立故障域发布哪些状态、如何组成可恢复检查点，以及最慢的保护路径是否会拖慢训练”。** 从逻辑压缩到物理保护之间存在一个独立的优化问题。它既不是另一种张量压缩，也不是简单挑两个拥有完整相同状态的 rank 互为副本。

设并行计划为 `P`。第一层 M1 固定 `P`，依据已确认的冗余关系、每个逻辑训练状态的需求、实际持有者及故障域，构造**对象级保护组与发布/放置计划**。第二层 M2 在有限的、预先验证的训练并行计划和物理映射中选择 `P`，对每个候选调用**同一 M1**，权衡训练与保护代价。第三个横贯贡献是恢复约束下的**发布者、网卡与目标端服务负载均衡**，不是第三套独立优化器。它们是研究问题与条件性贡献；当前已证实的是 M1 的部分端到端能力，M2 还没有完成实验。

最好的摘要级表述可用：“冗余感知的检查点将状态压缩问题转化为恢复约束下的物理保护问题：在保证同一提交时刻的完整恢复前提下，如何选择互补的状态来源及其跨故障域的驻留位置，减少重复传输并控制最慢发布路径？”不要写“发现没人优化分组”或“提出比 AdaCheck 更好的冗余检测”。已有研究确实做过 checkpoint group、replica placement 和 failure probability；独立性来自**状态需求、自然冗余、故障域、增量依赖及瓶颈服务资源共同决定保护计划**，不是“grouping”一词本身。

系统论文适配度是**有条件的**：若四机上的 M1 可恢复保护、强 baseline 下的 M2 联合收益、持续运行服务率和真实 host/rank 故障恢复闭环成立，具备 FAST/OSDI/MLSys 式的系统设计、机制和评估主线；仅两次短运行上的“字节减少”或离线图，尚不构成相同级别的系统论文证据。关于特定会议录用等级不作保证。

## 二、领域主线、缺口及与已有工作的区别

这条主线不是“人人都忽略分组”：传统持久化检查点将恢复状态保存在外部介质；内存保护通过相互备份降低故障后重启成本，随之引入复制流量、故障相关性和训练干扰；进一步的冗余识别降低应保存的数据量，但使剩余对象的来源、保护位置和恢复依赖变得不均匀。于是，性能决定因素由“逻辑 checkpoint 有多大”变为“在给定故障模型下，哪份**经提交且版本一致**的状态在哪个独立域，哪条物理边最晚完成，恢复时缺的对象能否拼齐”。

| 研究方向 | 核心问题 | 留给本研究的空间及公平比较 |
| --- | --- | --- |
| GEMINI（SOSP 2023） | 内存副本、分组/环与机器故障风险、检查点流量调度 | 已研究分组与副本放置；不能宣称首创 grouping。比较点是其以副本/故障组织为主，而本文进一步以**不均匀的对象等价类和完整恢复需求**选择来源、目标域及服务负载。按同等副本/故障预算比较，其相邻 rank 组是清晰的固定基线，但需验证在给定映射下是否跨机。 |
| AdaCheck（FAST 2026） | 探测跨 worker 及跨迭代冗余，降低需保护的状态，并追求高频增量检查点 | 其探测器是共同输入，而不是本文贡献。AdaCheck 也按照并行结构组织 worker group；本文的缺口是**探测后的、物理故障域内可恢复的对象级发布与驻留决策**，不能说它完全没有分组。公开工件不包含完整可执行的远端恢复路径，正式比较必须在**同一自建可恢复运行时**实施 AdaCheck 风格固定策略。 |
| ECCHECK（ICDCS 2025） | 内存纠删码、节点故障容忍和存储开销 | 编码容错是不同轴；若比较，必须固定可容忍的故障数、额外内存、恢复能力，不能只比较发送字节。 |
| CheckFreq（FAST 2021） | 检查点频率与成本的选择 | 频率是优化指标和另一优化轴；更频繁不能以未提交或队列积压的 epoch 冒充。 |
| FlowCheck（EuroSys 2025） | 利用训练通信流、解耦生成/传播与训练前台 | 这是不阻塞训练的强关联方向；若只压低字节但 CPU 后台长尾仍使训练等待，本文没有完整系统收益。 |
| Malleus（SIGMOD 2025） | 对慢节点等扰动重配训练并行度 | 训练并行计划会影响保护机会，但它的训练分组不能自动替代本文的恢复组；M2 不是重新实现通用并行搜索。 |

近邻边界也应主动陈述：UCP、ByteCheckpoint 的全局状态标识/重分片有助于解决**如何把已有状态加载到目标布局**，但不回答恢复约束下**在保存时**哪些来源应向哪些故障域发布；已有冗余感知系统也可能联合某种 placement，最终“新颖性”要靠相关工作逐项机制核对与严格 ablation，不靠“首次”断言。不能将纠删码、复制策略或重分片实现说成无人研究。

区别于普通固定副本放置的最小反例：两个 rank 可以分别保存两个不同参数切片，但某些模型/优化器对象天然等价。简单选择两个 rank 的相邻副本位置，并不自动回答不同逻辑 rank 所需切片是否齐全、可否利用目标域已有的等价对象、失去整台主机后能否恢复，或一名发布者是否成为长尾。本文的决策单位是**有角色、全局切片、版本与依赖的规范化训练状态对象**，优化结果是可验证的保护计划，不是仅靠 rank 对的相似度排序。

## 三、引言五段式及可检验的系统洞察

1. **大规模训练与故障代价。** 并行训练损失一次进度会浪费多机算力；频繁检查点降低重算，却同时增加存储、通信与前台干扰。第一段建立问题的经济尺度与端到端指标，不先展示算法。
2. **已有内存检查点。** GEMINI 等用 CPU 内存中的跨机器保护加速恢复，但复制、故障相关性和共享链路/服务的竞争成为硬约束；频率和恢复能力是相互制约的量。
3. **冗余检测打开机会。** DP/TP/PP/EP 等训练策略和迭代更新使状态形成不同范围的自然冗余；AdaCheck 说明这些冗余可以被探测和利用。不过**压缩后的对象集合仍要分配来源与放置**：逻辑冗余不等于物理可恢复性。
4. **缺失的可恢复分组问题。** 固定 worker pair 或固定 replica group 对对象级不均匀重叠、host 相关失效、增量依赖与物理瓶颈不敏感。用一个小图/例子：两个计划保存同一组逻辑必需状态，只有一个在主机故障后仍有完整同一 epoch 的状态；或者都正确，但一个重复跨机发布、一个集中堵在同一网卡。**切入点是“检测之后的物理保护决策”，而不是“别人不知道 checkpoint grouping”。**
5. **洞察、设计和证据。** 提出以完整恢复要求为硬约束的对象级保护组 M1，用 CPU 内存服务保存经提交的规范化对象，允许多来源装配；用 M2 比较受约束的并行/故障域映射，并把最忙链路与服务负载纳入目标。贡献按“问题/正确性合同—系统实现—实验量化”组织。已经观察到的端到端数据标注试验范围；未闭合的 M2、持续频率与故障不写成成果。

论文中间的系统图建议是：`并行布局 P → 稳定冗余证据/恢复对象图 → M1 的发布者+跨域保护计划 → 有界传输/同 epoch 原子提交 → CPU 服务 → 故障后多来源组装与继续训练`，M2 作为外层对 `P` 与 rank-to-domain 映射的有限候选搜索。Detector、grouping、encoder、transport、restore 是不同模块；把监测训练空闲/通信的 profile 作为独立观测模块。图上标记训练 parallelism group 与 checkpoint protection group 是两张不同的图。

## 四、严格的 group 语义与正确性

**术语。** 并行组由训练计划决定（DP 副本、TP 切片、PP 阶段、EP 专家）。*Checkpoint group* 在接口上仍是一组参与互存的 rank/worker：它们向组内其他主机上的 CPU 内存服务发布所需状态，使故障后的幸存方能够重建目标 rank，必要时重建整个作业。对象级保护计划进一步指定组内每个状态的实际发布者、目标故障域和恢复来源；它不修改训练进程组，也不要求每个 rank 只能从单一 peer 获取完整状态。数学上可以把 rank 组投影为对象—服务保护图。**组内所有 rank 在故障前的状态并集齐全，只证明无故障覆盖，不证明故障后仍有可用副本**。

用户提出的“组内 rank 互存其他 rank 的 checkpoint 参数副本”是本研究 CPU 内存保护的基础语义，但副本可按对象分配给不同组员，而非默认每个 rank 都存整个组的所有状态。这样既保留互存与从幸存者恢复的含义，也允许消除同一目标域内的重复保护；不能仅凭组内 union 就声称节省内存且可容错。如果恢复限定为从**单个**幸存 peer 直接加载某故障 rank 的完整状态，该 peer 必须持有全部相应状态；本文对象级恢复允许**多个**幸存来源共同装配，这需要独立的正确性证明，不能当作 AdaCheck 原论文已经实现的单 peer 恢复路径。CPU 服务与同机计算 rank 的相关故障必须显式建模。

**形式模型。** 固定提交 epoch `e` 和并行计划 `P`。令 `Q_e(P)` 是重启整个作业所需的逻辑状态切片和不透明状态需求（模型、优化器、学习率/缩放器、随机状态、数据采样/迭代位置）。`O_e` 是带规范化标识、角色、全局范围、类型、精确值/校验和、版本的候选对象，`D(o)` 是重建对象必需的 base、增量或其他依赖。`H_P(o)` 是**已被确认持有该对象同一版本**的天然 rank 持有者，物理服务域集合为 `V`。不同 PP/TP 切片不得只因数值偶然相同就被视为可替换的完整训练状态；具有语义上相同的角色与全局切片时，才按验证过的等价关系复用。保护计划 `π=(G,p,x,t)` 包含 rank/worker 组 `G`、各对象合法发布者 `p(o)∈H_P(o)`、服务域放置 `x(o)⊆V` 及其提交/传输安排 `t`。允许同一对象在多个故障域各驻留一份；不能把两个目标副本合算成一份逻辑字节。

对故障集合 `F`，记 `A_e(F,π)` 为排除失效计算 rank 与服务域后，**仍驻留在幸存 CPU 服务上**且同一提交 epoch 校验通过的对象集合；健在的计算 rank 只有在其内存状态明确纳入保护合同并通过同等验证时才能作为额外来源，不能暗中计为副本。`Closure(A)` 为在完整依赖链可用条件下可精确重建的状态切片。可恢复性的基本条件是：

```text
∀F ∈ ℱ, ∀q ∈ Q_e(P):  q ∈ Closure(A_e(F, π)).
```

这里的 `ℱ` 必须明确包含哪些 rank、host 以及二者的相关失效；`Closure` 不能把重叠但值不一致的范围、不同 epoch 或缺少底座的梯度增量视为覆盖。无故障时的 `F=∅` 只是 state coverage；对每个声明的 `F` 都成立才是 fault-tolerant state coverage。元数据需要原子绑定 catalog/parallel-plan/group-plan/encoder、epoch、校验和，并在装配前验证。恢复正确性的可证部分是“若每个精确切片和依赖均通过校验，拼合唯一决定目标完整状态”；训练继续的一致性还依赖 RNG、sampler 等不透明状态的语义变换得到定义并实测。

对于**每个必需对象都以完整、相同版本直接复制；不依赖其他对象重建，且故障只删除对应副本**的特例，要容忍任意 `f` 个独立 rank 失效，每个对象至少须有 `f+1` 个**不同 rank 承载的 CPU 副本**；要容忍任意 `f` 台主机失效，则每个对象至少须有 `f+1` 个**不同主机上的 CPU 副本**。在同一已提交 epoch、所有必需对象及不透明状态都这样复制、且剩余资源足够重启的前提下，这个逐对象条件才是存储覆盖的必要且充分条件。通常应直接检查上面的每个 `F`：切片需精确覆盖，增量需要基础版本与更新链，编码冗余也有自己的可解码条件；一味数 `f+1` 份不够。同一主机上三个副本不能抵抗整机故障；保存于故障主机的 CPU 副本也会同时消失。

特别地，在**仅两台独立主机**、每台一份 host-pooled CPU 服务、要求丢失任意一台后仍可重建**整个作业**，且无第三方/持久化后备的合同下，两个主机各自的已提交内容都必须足以覆盖 `Q_e(P)`。这给采用**相同对象表示和编码**且经主机去重后的字节数设置了下界：若两主机各自已拥有每个必需对象的一份同版本副本，单靠重新配对 rank 不可能再减少所必需的主机级跨域保护字节。较粗的固定 worker 分组若反复发布同一对象，改为按目标域池化可减少这些**重复保护开销**；进一步 M1 调整发布者通常改变负载和时间，而不是同一池化合同下的必需字节。四台或更多主机出现更有意义的目标域选择和失效后可用来源组合。

“不依赖特定并行布局”应写成**算法和状态标识不把 PP/TP/DP/EP rank 坐标硬编码为固定 peer**：对于能提供完备 `Q_e(P)`、无冲突全局切片、稳定对象等价证据与不透明状态变换的受支持布局，同一覆盖判定与优化器适用。不同布局仍须重新生成持有者/对象图；不能保证任意布局都有非零优化空间，也不能声称任意布局已有可运行适配器或总能求全局最优。

## 五、优化目标：让字节、内存、时间与故障预算可比较

将可靠性、可提交、内存/队列容量、可用剩余算力、最大可接受恢复点和恢复时间列为**硬约束**。在同等故障预算和副本容量合同下，按预注册权重或词典序最小化 `(暴露给训练的检查点关键路径，最忙发布者/网卡/服务资源负载，跨域 application 与 wire bytes，额外 CPU 驻留内存，恢复尾部，计划切换成本)`。逻辑对象的独立数量不等于网络实际发送字节：编码、封包、重传、两份目标副本、D2H/CPU apply 都需要单独测量。总 transfer size 在候选之间可能降低，但最慢边时长受共享网卡、服务端和排队影响，不能从 `bytes ÷ 100Gbps` 直接推导。

当性能主张从 M1 提升到 M2 时，需要同时满足训练计划有效性和同一 M1 函数：

```text
M1(P) = best recoverable protection plan under fixed P.
M2    = argmin_{P in preregistered validated candidates} Joint(training(P), M1(P)).
```

比较对象至少包括 `training-only-best P + best post-hoc M1(P)`；否则只是选了一个对 checkpoint 有利而对训练不利的布局。有限候选上的穷举可作为已知最优参照，不能宣称一般对象/布局联合问题有可扩展的全局最优算法。若先验 100Gbps 网络下瓶颈变成 CPU 物化，M1 应报告性能失败并解释下界，而不是用逻辑字节的改善掩盖尾部。

## 六、评估方案：每个实验对应一个可反驳的主张

### A. 微基准和机制拆解

使用合成与实测状态目录，系统改变天然等价类的分布、模型/优化器对象比例、对象尺寸偏斜、DP/TP/PP/EP 持有者关系、CPU 服务域数量/容量、故障预算、链路竞争和 base/增量深度。比较固定组、GEMINI 相邻组、随机可行组、仅最大冗余、`HostGlobalFixed` 及 M1。任何不可恢复的组不得进入等同故障预算的性能柱状图；可作为“仅离线上界”。在小实例给最优解/最优性差距，在大实例报求解开销和扩展趋势；对内存容量、网络瓶颈、recovery RTO 进行敏感性分析。

主要量表：每一轮 16/32 rank *total* 跨故障域 application 与 wire bytes；各服务驻留/峰值 CPU 内存；checkpoint 从 capture 到全局 seal 的 p50/p95/p99 和最慢**物理资源**尾部；按 D2H、序列化、发送、队列等待、CPU apply、全局提交拆解；恢复的加载、装配、重分片、状态应用与首个成功继续训练步的实际用时。计量级别要标注 logical、application、NIC，不能把本地拷贝计作跨机网络，也不能把最慢 PUT 直接等同全局提交时间。

**归因实验不可省：** `FullState → 同一 AdaCheck 风格 detector+encoder 下的 AdaCheckStyleFixed → HostGlobalFixed → M1Object`。第一差值属于冗余识别/编码；第二差值隔离粗粒度固定组在共享服务上的重复保护；第三差值主要隔离发布者选择和负载安排。当前两个 dense 严格套件恰呈现 Host 与 M1 suffix 逻辑字节近乎相同的情况，不能将 Ada-to-M1 的全部字节改善宣传成“一个更聪明的 rank pair”单独造成。

### B. 故障容忍：按实际失效范围与恢复计划成二维矩阵

两条轴：计算失效为**单 rank**或**整机全部 ranks + 同机 CPU 服务**；恢复计划为**原布局不变**或**更改布局/物理映射并重算保护计划**。在固定 optimizer step、检查点正在传输时终止进程（rank 使用 `SIGKILL`，主机使用隔离/终止该主机整个 worker 与服务 stack，并验证幸存主机读不到故障域内存）；必要时从备用 GPU/主机重启。每一轮先检查已提交 epoch（部分提交不可见），再在新的分布式 job 中装配，比较 model、optimizer、scheduler、RNG、sampler、iteration 与不故障参照的继续训练结果。报告恢复成功率、丢失步骤/RPO、重建/RTO 与首步成功时间、重分片/计划生成/计划切换时间和峰值内存。多次重复不同注入时刻。

严格区分“丢失 checkpoint service 进程”、“重新启动原 host stack”和“**物理主机永久消失**”：前者不能证明后者。在 16-rank 两机且没有备用训练资源时，失去一台 8-GPU 主机后无法凭空维持原 16-rank 布局；需要备用节点或一个验证过的缩容 `P'`。四机是 host-loss、故障域选择与 M2 的重要实验平台。对比 AdaCheckStyleFixed、HostGlobalFixed、M1Object 的同约束恢复；与 GEMINI、ECCHECK 的跨系统比较必须固定故障数、冗余内存和可恢复职责，公开代码不足时明确为论文语义的受控策略基线而非声称复现其完整运行时。

### C. 端到端训练与失效率

不必完成数十亿 token 的模型收敛来论证检查点机制；必须完成**充分长、真实执行 forward/backward/optimizer 的运行窗口**以观察持续服务率和稳定尾部。使用至少 200 个 optimizer step 的预注册试验，按当前服务率逐步测真实可持续的每 `N` 步一份（如 `N=16,8,4,2,1`，实际可行值优先）；1C1S 是最终上界目标，**不是先做 M1 正确性实验的入场券**。分别记录配置频率、实际连续 globally committed 次数/训练总步骤、可见滞后、丢弃/合并、队列峰值、最后 drain、单步 wall-time 分布及 checkpoint completion。若 `N=1` 但提交晚多步，只能称“每步捕获”，不能称“每步都可恢复”。

报告训练总用时、有效吞吐（成功恢复后的有效进度/含失败和重算在内的总时间）、前台被 checkpoint 暴露的阻塞、最忙边和端到端封存时延、CPU/网络容量、恢复后额外损失时间；在同一测得的 checkpoint/RTO/RPO 分布上扫描不同失效率。真实注入验证故障行为，解析式/回放的失效率扫描标注为**模型推算**，并做故障独立性与相关主机失效的敏感性分析。`NoCheckpoint` 只用于训练开销下界；M1 的正式比较是相同训练 workload、detector、active encoder、CPU 服务预算、传输、提交、容错合同下的 AdaCheckStyleFixed，另用 HostGlobalFixed 隔离负载效果。对于 M2，再加最快训练-only 布局的 post-hoc M1。

模型矩阵建议先用 BERT/GPT-2/LLaMA-like-3B 六个 frozen-catalog 单元展示**机会来自何处**，不把它们包装为真实故障恢复：目前 PP4/TP2/DP2 的 RedundancyMax 相对固定减少 `23.022%/71.054%/24.851%`，PP4/TP1/DP4 为 `18.419%/19.130%/5.768%`；其中 LLaMA-like-3B DP2 的随机策略可退化 `159.194%`。这是早期跨主机配对观测，不能与端到端主机失效约束混写。正式实验先用已具备部分证据的两个 dense 模型（LLaMA-3-8B、GPT-6.33B）扩展到两种各自有效的布局和 200 步，再为两个 MoE 模型实现并验证专家状态身份及 EP 适配，最后在获得明确许可后推进 32-rank/四机 M2；不默默缩小模型或把不支持的 EP 当成已完成。

- “两个主机根本不能验证 host grouping”：承认该下界，在 ≥4 独立主机测目的域选择、故障域均衡、host-loss 与联合 M2，并与最强先训后保基线比较。

- “实验是模拟 AdaCheck 或挑有利布局”：原始工件的可达范围、共用的 AdaCheck 风格固定组、论文语义补全与相同 detector/encoder/runtime 如实分栏；预注册多布局、多重复和负例；不能跨系统直接用论文数字构造速度比。
- “为何不只引入 UCP”：重分片解决恢复时**如何载入**，不是故障发生前**哪些对象应复制、放在哪里、谁发布**；用相同装配器固定变量证明 M1 带来的效应。

# 从冗余到保护：面向大模型训练的故障域感知检查点分组

*From Redundancy to Protection: Failure-Domain-Aware Checkpoint Grouping for Distributed Training*

### 摘要

内存检查点通过在训练节点间保存状态，缩短大模型训练的故障恢复时间，但副本的传输和驻留又会争用训练资源。已有冗余感知方法识别哪些参数和优化器状态可以被复用；一个尚未被充分刻画的问题是：识别出冗余后，应该由谁发布每个必需状态、让哪些节点共同保护它，以及如何在故障后从幸存节点恢复完整训练状态。我们将检查点分组视为受恢复约束的保护计划，而不是训练并行组的另一种表示。对于给定的并行布局，系统根据训练状态的自然冗余和主机故障域选择对象来源与 CPU 内存中的副本位置，同时约束最忙发布者的负载。进一步，训练状态的分布本身取决于并行布局，因此我们研究在有效布局之间联合选择训练放置与检查点保护计划。在两台主机、16 个训练进程的初步端到端实验中，两个稠密模型相对同一运行时上的固定分组基线，包含共同基础检查点在内的传输量分别降低 18.2% 和 40.0%，且在检查点服务失效后从已提交状态恢复并继续训练。更长时间的持续吞吐、真实主机故障，以及四主机上的联合优化仍待验证。

### 1. 引言

大模型训练越来越依赖多维并行：同一参数可能出现在多个数据并行副本中，也可能被张量并行切分；不同流水阶段与专家持有不同的状态。故障恢复要求保存的不只是模型权重，还包括优化器、训练进度和随机性相关状态。频繁将它们写入远端存储会付出可观的传输与停顿代价，因此 GEMINI 等工作转向由训练机器在内存中相互保护检查点，研究如何控制副本流量和故障风险。[1]

冗余感知进一步改变了问题。AdaCheck 表明，训练状态在 worker 之间及迭代之间的天然冗余可以减少需要传输的内容。[2] 然而，**知道两个状态相同，不等于知道把它们放在哪里才安全**。即使同一组状态已经被去重，两个把副本放在同一主机上的计划与放在不同主机上的计划，在单主机故障下也有完全不同的恢复结果；两个都能恢复的计划，如果由同一发布者串行发送大量对象，训练所见的检查点尾部仍可能不同。原有并行组刻画训练计算，并不直接规定这组状态应怎样跨故障域驻留。

我们的研究问题是：给定已确认的状态等价关系、每个逻辑训练进程的恢复需求及机器拓扑，怎样组成检查点保护组，使失去指定故障域后仍能重建最新已提交的完整状态，同时降低跨机流量和保护的最慢路径？这一问题与传统副本选择不同：保护对象可能由多个训练进程持有，恢复需求可能是不同来源的互补切片，且压缩、复制和恢复依赖必须属于同一提交时刻。也不同于冗余检测：分组不会创造新的状态等价关系，只决定已有关系中有多少能安全地用于保护。

我们从两个相互关联的观察出发。第一，在固定训练布局下，只有将状态的自然持有者、待恢复对象和目标故障域放在同一张图中，才能选择不重复发布且可恢复的保护计划。第二，训练并行布局改变这张图：同一模型在不同的 DP、TP、PP 或 EP 配置下拥有不同的状态切片、可替代来源和网络争用。因此，仅在预先固定的并行布局上优化分组，可能错过更好的训练—保护折中；反过来，只选训练最快的布局，再补上检查点，也可能无法降低故障后的有效完成时间。

为此，我们设计两层决策。第一层针对固定训练布局，为每个必需对象选择发布来源、CPU 内存中的保护域及传输安排，并在选择之前检查声明的故障后能否拼回完整状态；它同时限制最忙发布者和服务节点的负载。第二层在一组已经证明可运行的并行布局与物理映射中，调用**相同的第一层算法**评估保护成本，选择训练与恢复都可接受的配置。训练并行组决定状态如何产生；检查点组决定状态如何受保护。二者相关，但不应相同。我们的目标不是给 AdaCheck 加一个配对选项，而是建立一个以**可恢复对象需求**为中心的系统抽象，贯通冗余信息、故障域与并行布局。

当前工作的贡献分为三个层次。首先，我们定义对象需求与故障域覆盖的检查点分组问题，说明仅凭组内状态并集无法证明容错。其次，我们实现了在固定训练布局下的对象级保护、CPU 内存驻留和多来源恢复原型，并将发布负载纳入优化。最后，我们提出并将评估并行放置与检查点保护的联合搜索，以训练-only 最优布局再单独优化检查点作为强基线。第三层目前是**待验证的系统设计**，不是现有实验结论。

### 2. 设计概览

系统接收的不是“某 rank 应该配给哪个 rank”这一孤立问题，而是某个已提交训练步上，每个模型切片、优化器状态及运行进度**需要哪些值才能恢复**，以及这些值已由哪些训练节点自然持有。前端冗余检测器只提供经确认的相同状态；我们的规划器并不替代检测器。对每个候选对象，系统选择可以发布正确版本的源节点，并将足够的对象或副本发送到位于适当故障域的 CPU 服务。相同值在目的域已经可用时，不必因为另一个固定 rank 组再次发布；但该跳过动作必须以相同训练步、依赖完整及失效后仍可获取为条件。

检查点提交采用整轮语义：只有该轮要求的对象和它们的基础版本都可在声明故障下重建时，整个训练步才对恢复可见。恢复阶段不依赖故障 rank 的编号找文件，而按状态身份和全局切片从幸存服务获取对象，拼成目标布局所需状态，再继续训练。对于尚未定义随机数、采样游标或新并行布局转换规则的状态，系统拒绝声称能够变更布局恢复。这一保守界限是正确性的一部分。我们把“每步发起一次传输”和“每步都有一份已提交、可恢复检查点”分别计量，避免用后台积压冒充高频率。

在两个主机各保存足以恢复完整作业的状态时，重复对象经主机级池化之后，跨机必需字节存在自然下界：再改变 rank 配对不一定能继续减少字节。因此我们区分两个问题：固定分组到对象级池化所消除的**重复保护**，以及池化之后通过选择发布者和调度降低的**最忙资源尾部**。拥有更多独立主机时，目标域与故障后的可选来源才形成更丰富的分组空间；这是我们检验联合并行放置设计的主要场景。

### 3. 初步结果与评估计划

我们首先在早期小模型的冻结状态目录上观察到：改变跨机候选 rank 配对能够利用不同程度的既有冗余，随机分组也可能变差。这一实验只说明研究动机，不代表故障后可恢复的在线性能。在后续两台主机、16 个训练进程的可恢复原型中，我们对 LLaMA-8B 和 GPT-6.33B 使用相同的冗余证据、编码器、传输、服务容量与恢复流程，比较固定分组、主机级固定池化和对象级规划。与固定分组相比，包含共同基础检查点后的总应用层传输量分别减少 18.2% 和 40.0%；一次检查点服务失效后的新进程恢复与继续训练通过了完整状态校验。由于每种配置仍是很短的单次试验，不能据此声称稳定的训练提速、整机失效容忍或每步一份已提交检查点。

完整评估将回答三个问题。**第一，保护是否比仅去重更好？** 在同一故障预算下比较 GEMINI 风格固定组、AdaCheck 风格固定组、主机级池化、随机可行组及我们的对象级计划，区分检测器节省、重复保护节省与发布均衡；报告总跨机传输量、网络实际字节、CPU 内存峰值、最慢链路/服务完成时间和恢复延迟。**第二，是否真正改善训练？** 在真实训练中报告 200 步总时间、检查点对前台造成的等待、已提交检查点频率、失败后浪费的时间，以及不同故障率下的有效训练吞吐；如每步检查点不可持续，就报告实测可持续频率。**第三，联合选择何时有意义？** 在四机、多种有效并行布局上，把联合选择与“训练最快布局 + 其上最优检查点保护”直接比较，同时注入单 rank、整主机故障，测量从幸存 CPU 内存恢复后的继续训练。只有第二、第三个问题得到实测支持，我们才把长期吞吐和联合优化写成论文结果。

### 4. 讨论与结语

冗余感知检查点的价值并不止于找出“哪些字节可以不再保存”。真正决定它能否成为可靠训练系统的，是能否在故障域约束下，把剩余状态变成一份**可以及时提交、能够从幸存者重建、不会让一条物理路径拖慢训练**的保护计划。我们现有结果显示对象级保护在两个稠密模型上可以减少固定分组带来的重复传输；联合选择训练并行与保护位置、整机故障和持续频率仍属于下一阶段验证。若这些实验没有显示额外收益，论文应收窄为固定布局下的恢复约束分组，而不是把系统愿景当成已完成的实验结论。
